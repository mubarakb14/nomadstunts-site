# Сервер сайта и админка

Один Go-бинарник отдаёт лендинг и админку `/admin`. В админке можно менять шоурил, команду, основателя, проекты, фотогалерею и контакты, разработчик для этого не нужен.

## Как устроено

- **Данные:** весь контент лежит в `DATA_DIR/content.json`. Сайт получает его как `/assets/data.js`, файл генерируется на лету, поэтому HTML и JS сайта не знают про сервер.
- **Первый запуск:** `content.json` создаётся из `assets/data.js` в репозитории.
- **Загрузки:** фото и видео сохраняются в `DATA_DIR/media/` и отдаются по адресу `/media/…`.
  - Фото автоматически поворачиваются по EXIF (снимки с телефона), уменьшаются до нужного размера и сохраняются в JPEG.
  - Фото команды и основателя на прозрачном фоне (вырезки) остаются прозрачными, как у карточек на сайте. Они сохраняются в WebP через `cwebp`, который стоит в Docker-образе, а если его нет, то в PNG.
  - Видео сохраняется как есть.
- **История:** перед каждым сохранением прошлая версия копируется в `DATA_DIR/history/` (хранятся последние 60). Вернуть любую версию можно в админке, в разделе «История».
- **Что остаётся за разработчиком:** тексты интерфейса, история компании, услуги, слайды на главной и большие фото основателя. Это всё в `assets/app.js` и `assets/style.css`.

## Запуск локально

```bash
cd server
ADMIN_PASSWORD='придумайте-длинный-пароль' SITE_DIR=.. DATA_DIR=../data go run .
```

После запуска сайт открывается на http://localhost:8080, админка на http://localhost:8080/admin.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `ADMIN_PASSWORD` | да | Пароль админки, не короче 10 символов |
| `ADMIN_USER` | нет | Логин, по умолчанию `admin` |
| `SESSION_SECRET` | желательно | Любая длинная случайная строка. Без неё после перезапуска сервера всех выкинет из админки |
| `DATA_DIR` | нет | Папка с данными, по умолчанию `./data`. **Именно её нужно бэкапить** |
| `SITE_DIR` | нет | Папка с файлами сайта, по умолчанию `.` |
| `SITE_URL` | **да в продакшене** | Публичный адрес сайта, например `https://nomadstunts.com`. Из него строятся canonical, hreflang, sitemap и llms.txt. Если не задан, адрес берётся из запроса |
| `PORT` | нет | Порт, по умолчанию `8080` |
| `TRUST_PROXY` | нет | `1`, если сервер стоит за Nginx или Caddy. Тогда лимит неудачных входов считается по реальному IP посетителя |

## Деплой (Docker)

```bash
docker build -t nomadstunts .
docker run -d --name nomadstunts -p 8080:8080 \
  -e ADMIN_PASSWORD='…' -e SESSION_SECRET='…' \
  -v nomad-data:/data --restart unless-stopped nomadstunts
```

- **HTTPS:** перед сервером нужен прокси с HTTPS, например Caddy или Nginx. Можно взять и хостинг, который сам даёт HTTPS: Railway, Fly.io или Render с диском.
- **Диск обязателен.** Без него загруженные фото пропадут при перезапуске, поэтому Vercel для этой схемы не подходит.

## Защита

- **Вход:** один аккаунт админа из переменных окружения, сессия хранится в подписанной cookie (HttpOnly, SameSite=Strict, Secure при HTTPS) и живёт 7 дней.
- **Защита форм:** каждая отправка формы в админке проверяет CSRF-токен.
- **Подбор пароля:** после 10 неудачных попыток вход блокируется на 15 минут.
- **Проверка загрузок:** проверяются тип и размер файла (фото до 30 МБ, видео до 800 МБ), имена файлов генерируются случайно.
- **Закрытые файлы:** из `SITE_DIR` отдаются только страницы `*.html`, папки `assets/` и `upload/` и `favicon.ico`. Код сервера, `.git` и данные снаружи недоступны.

## SEO и AEO

- **Тексты сайта.** Интерфейсные тексты, услуги, история, FAQ, а также `<title>` и description для каждой страницы лежат в `assets/i18n.js` на трёх языках. Их читают и JS сайта, и сервер.
- **Сборка страницы.** Каждую страницу сервер отдаёт уже с нужным `<html lang>`, title, description, canonical, hreflang (en, ru, kk и x-default), Open Graph/Twitter и разметкой JSON-LD:
  - Organization, Person (основатель), WebSite;
  - на «О нас» добавляется FAQPage, на «Команде» — список людей, на «Проектах» — список фильмов (Movie/TVSeries), на «Галерее» — ImageGallery, плюс хлебные крошки.
- **Копия для ботов.** В начало `<body>` сервер вставляет `.ssr`: копию содержимого страницы обычным HTML для поисковиков и AI-ботов, которые не выполняют JavaScript. Когда JS работает, класс `js` на `<html>` скрывает её. Посетитель видит обычный сайт, бот — тот же текст.
- **Языки и адреса.** Английский открывается без параметра, русский по `?lang=ru`, казахский по `?lang=kk`. Адреса `/about.html` и `/index.html` редиректят (301) на `/about` и `/`.
- **Файлы для ботов** собираются из живого контента:
  - `/robots.txt`: открыт для поисковиков и AI-ботов (OAI-SearchBot, GPTBot, Claude, Perplexity, Google-Extended), закрыт только `/admin/`;
  - `/sitemap.xml`: 6 страниц × 3 языка, с hreflang;
  - `/llms.txt` и `/llms-full.txt`: краткая и полная справка о компании для AI-ассистентов.
- **Превью ссылки:** `assets/og-image.jpg`, 1200×630.

После запуска на домене:

1. Задайте `SITE_URL`.
2. Добавьте сайт в Google Search Console и Bing Webmaster Tools и отправьте `sitemap.xml`. Bing нужен потому, что ChatGPT и Copilot ищут через него.
3. Проверьте разметку в [Rich Results Test](https://search.google.com/test/rich-results).
